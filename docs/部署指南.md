# 航海集市 部署指南（Docker）

本文说明怎样把网站部署到一台云服务器上，以及上线后怎么更新、备份和排查问题。
本地开发方式不变（`python run.py` + `npm run dev`），Docker 只在服务器上使用。

## 1. 整体结构

```
同学的浏览器 ──80 端口──▶ ┌─────────────── 云服务器（Ubuntu + Docker）───────────────┐
                          │  frontend 容器        backend 容器        db 容器        │
                          │  Nginx + 前端页面 ──▶ FastAPI 后端 ──▶ PostgreSQL 17   │
                          │        │                   │                  │         │
                          │        └── uploads 数据卷 ──┘          db-data 数据卷    │
                          └─────────────────────────────────────────────────────────┘
```

| 容器 | 镜像来源 | 作用 | 对外开放 |
|---|---|---|---|
| `frontend` | `frontend/Dockerfile`（Node 打包 → Nginx） | 提供前端页面；`/api` 转给后端；`/uploads` 直接读图片 | **80 端口** |
| `backend` | `backend/Dockerfile`（Python 3.14） | 业务接口、AI 助手 | 不开放，只有 Nginx 能访问 |
| `db` | 官方 `postgres:17` | 数据库 | 不开放 |

- **数据卷**：`db-data`（数据库文件）、`uploads`（上传的图片）。容器删除重建，数据仍然保留。
- **密钥**：都在服务器项目目录的 `.env` 里，不进镜像，不进 Git。模板是 `.env.production.example`。
- **代码传输**：开发电脑通过 SSH 直接推送到服务器上的 Git 仓库（国内服务器访问 GitHub 不稳定），GitHub 作为备份。

相关文件：

| 文件 | 作用 |
|---|---|
| `docker-compose.yml` | 定义三个容器、两个数据卷以及它们的连接关系 |
| `backend/Dockerfile`、`frontend/Dockerfile` | 后端、前端镜像的打包说明书 |
| `frontend/nginx.conf` | Nginx 转发规则、缓存、压缩、上传大小限制 |
| `.env.production.example` | 服务器 `.env` 的模板 |
| `deploy/init-server.sh` | 第一次上线：生成 `.env`、启动容器、导入演示数据 |
| `deploy/update.sh` | 更新：备份 → 拉代码 → 执行数据库升级脚本 → 重新构建 → 重启 |
| `deploy/backup.sh` | 备份数据库和图片，保留 7 天 |

## 2. 服务器准备（只做一次）

当前服务器：腾讯云轻量应用服务器，广州，4 核 4G，Ubuntu 24.04，公网 IP `111.230.152.200`。

1. **防火墙**（云控制台）：只放行 22（SSH）、80（HTTP）、Ping。数据库端口不放行。
2. **SSH 只用密钥登录**：开发电脑生成密钥，公钥写入服务器 `~/.ssh/authorized_keys`；
   服务器 `/etc/ssh/sshd_config.d/00-hanghai.conf` 关闭密码登录和 root 登录。
   开发电脑 `~/.ssh/config` 里配置了别名，登录命令是 `ssh hanghai`。
3. **系统更新**：`sudo apt-get update && sudo apt-get -y upgrade`，提示需要重启时重启。
4. **安装 Docker**（Docker 官方的 Docker CE，从腾讯云内网镜像站下载，安装前核对官方公钥指纹
   `9DC8 5822 9FC7 DD38 854A E2D8 8D81 803C 0EBF CD88`）：
   ```bash
   sudo install -m 0755 -d /etc/apt/keyrings
   sudo curl -fsSL https://mirrors.tencentyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
   gpg --show-keys /etc/apt/keyrings/docker.asc      # 核对指纹
   echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.tencentyun.com/docker-ce/linux/ubuntu noble stable" | sudo tee /etc/apt/sources.list.d/docker.list
   sudo apt-get update
   sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
   sudo usermod -aG docker ubuntu                    # 以后不用每次加 sudo（重新登录后生效）
   ```
5. **Docker 配置** `/etc/docker/daemon.json`（镜像加速器 + 限制日志大小），改完 `sudo systemctl restart docker`：
   ```json
   {
     "registry-mirrors": ["https://mirror.ccs.tencentyun.com"],
     "log-driver": "json-file",
     "log-opts": { "max-size": "10m", "max-file": "3" }
   }
   ```

> 换成阿里云等其他厂商时，需要改三处镜像地址：上面的 Docker 安装源和加速器，
> 以及两个 Dockerfile 里的 `PIP_INDEX_URL`、`NPM_REGISTRY`。

## 3. 第一次上线

**① 在服务器上建一个接收代码的 Git 仓库**（服务器上执行）：

```bash
git init --bare ~/hanghai.git
```

**② 从开发电脑把代码推过去**（开发电脑的项目目录里执行）：

```bash
git remote add server hanghai:hanghai.git
git push server main
```

**③ 在服务器上取出代码并初始化**（服务器上执行）：

```bash
git clone ~/hanghai.git ~/hanghai
cd ~/hanghai
bash deploy/init-server.sh      # 第一次运行：生成 .env（随机密钥）后停下
nano .env                       # 填写 LLM_API_KEY（DeepSeek 的 Key），Ctrl+O 回车保存，Ctrl+X 退出
bash deploy/init-server.sh      # 第二次运行：构建镜像、启动容器、导入演示数据
```

第一次构建要下载基础镜像和依赖，需要几分钟。完成后用浏览器打开 `http://111.230.152.200`。

演示账号的学号见 README（`20230001` 管理员等），**密码是 `.env` 里的 `SEED_PASSWORD`**（随机生成，查看：`grep SEED_PASSWORD .env`）。

**④ 设置每天自动备份**（服务器上执行一次）：

```bash
(crontab -l 2>/dev/null; echo "0 3 * * * cd ~/hanghai && bash deploy/backup.sh >> ~/backups/backup.log 2>&1") | crontab -
```

## 4. 日常更新

开发电脑上改好、测试通过、提交之后：

```bash
git push origin main      # 备份到 GitHub
git push server main      # 推到服务器
ssh hanghai "cd ~/hanghai && bash deploy/update.sh"
```

`update.sh` 会先备份，再拉取代码、执行数据库升级脚本、重新构建、重启容器，大约一两分钟。数据库里已有的数据和图片不受影响。

- **只改了 `.env`**（比如换 Key）：`docker compose up -d` 即可，会用新配置重建后端容器。
- **改了数据库表结构**：`schema.sql` 只在数据库第一次创建时执行，之后不会自动执行。
  做法是在 `backend/sql/` 下写一个升级脚本，文件名以 `upgrade_` 开头（如 `upgrade_T16_wall.sql`），
  同时把同样的改动写进 `schema.sql`（给全新安装用）。`update.sh` 每次更新都会把所有 `upgrade_*.sql` 按文件名顺序执行一遍。
  **升级脚本必须可以重复执行**：建表用 `CREATE TABLE IF NOT EXISTS`，加列用 `ADD COLUMN IF NOT EXISTS`，
  插入数据用 `ON CONFLICT DO NOTHING`。这样不用记录「哪些已经执行过」。手动执行某一个：
  ```bash
  docker compose exec -T db psql -v ON_ERROR_STOP=1 -U campus_app -d campus < backend/sql/upgrade_T16_wall.sql
  ```
- **退回上一个版本**：`update.sh` 结束时会打印退回命令（`git reset --hard 旧版本号 && docker compose up -d --build`）。

## 5. 备份与恢复

备份文件在服务器 `~/backups/`：`db-日期.sql.gz`（数据库）和 `uploads-日期.tar.gz`（图片），保留 7 天。

把备份下载到开发电脑（开发电脑上执行）：

```bash
scp "hanghai:backups/db-*.sql.gz" .
```

恢复数据库（**会覆盖现有数据**，服务器项目目录里执行）：

```bash
docker compose stop backend
docker compose exec -T db psql -U campus_app -d postgres -c "DROP DATABASE campus" -c "CREATE DATABASE campus"
gunzip -c ~/backups/db-20261111-030000.sql.gz | docker compose exec -T db psql -U campus_app -d campus
docker compose start backend
```

恢复图片：

```bash
docker compose exec -T backend tar -xzf - -C /app < ~/backups/uploads-20261111-030000.tar.gz
```

> `.env` 里的 `WECHAT_AES_KEY` 也要另外保存一份：丢了它，数据库里加密的微信号就解不开了。

## 6. 常用命令（服务器项目目录 `~/hanghai` 里执行）

| 命令 | 作用 |
|---|---|
| `docker compose ps` | 三个容器的状态，正常应都是 `running`，db 是 `healthy` |
| `docker compose logs -f backend` | 实时看后端日志（`Ctrl+C` 退出）；换成 `frontend`、`db` 看另外两个 |
| `docker compose logs --tail 100 backend` | 后端最近 100 行日志 |
| `docker compose restart backend` | 重启后端 |
| `docker compose down` | 停止并删除容器（**数据卷保留**，数据不丢） |
| `docker compose up -d` | 启动 |
| `docker compose exec db psql -U campus_app -d campus` | 进入数据库命令行（`\q` 退出） |
| `docker stats --no-stream` | 各容器占用的内存和 CPU |
| `df -h /` 、`docker system df` | 硬盘空间、Docker 占用的空间 |

⚠️ **不要执行 `docker compose down -v`**：`-v` 会删除数据卷，数据库和图片全部丢失。

## 7. 常见问题

| 现象 | 排查 |
|---|---|
| 浏览器打不开 | `docker compose ps` 看容器是否都在运行；云控制台防火墙是否放行 80 |
| 页面能开，但提示「请求失败（502）」 | 后端没起来：`docker compose logs --tail 50 backend`。常见原因是 `.env` 里某个密钥格式不对 |
| 小航总是「AI 助手暂时不可用」 | `.env` 里 `LLM_API_KEY` 没填或余额用完；或者当天已达 `ASSISTANT_GLOBAL_PER_DAY` 上限。日志里有 `AI 助手降级：原因` |
| 上传图片失败（413） | 图片超过 5MB |
| 构建时下载很慢或失败 | 检查 `/etc/docker/daemon.json` 的加速器；重试一次 |
| 从国外 SSH 连接偶尔超时 | 跨国网络抖动，重试即可 |
| SSH 密钥丢了进不去 | 云控制台 →「登录」→ VNC 方式，用实例密码进入；或在控制台重新绑定密钥 |

## 8. 安全措施一览

- 服务器只开放 22、80 端口；数据库和后端不对外，只在 Docker 内部网络里互通
- SSH 只允许密钥登录，禁止 root 登录
- 所有密钥在服务器的 `.env`（权限 600），随机生成，与开发环境不同
- 演示账号使用随机密码，不用公开的 `Test1234`
- 后端容器以普通用户运行；Nginx 对图片目录只读
- Nginx 用访客真实 IP 覆盖 `X-Forwarded-For`，限流不能被伪造的请求头绕过
- AI 助手：单人每分钟 / 每天限流 + 全站每日总次数上限，超过自动降级
- 校园墙：先审后发；普通接口不返回投稿人；图片上传前在浏览器里去掉拍摄地点等隐藏信息
- 每天自动备份数据库和图片，更新前也会先备份

## 9. 以后要做的（正式开放给全校之前）

- **域名 + ICP 备案 + HTTPS**：目前用 IP 和 HTTP 访问，密码在网络上是明文传输，只适合内部测试；
  微信小程序也要求备案域名和 HTTPS。届时在 Nginx 增加 443 和证书配置，防火墙放行 443。
- **注册验证**：现在注册只检查学号是 6–20 位数字，校外的人也能注册。校园墙「只给本校学生看」依赖这一点，
  正式开放前要加上邀请码或学校邮箱验证，并按本校规则校验学号（12 位，前 4 位是入学年份）。
- **图片压缩**：服务器带宽 3M。校园墙的图片已经在上传前压缩；二手物品的图片还没有，可以用同一个工具（`frontend/src/lib/image.js`）。
- **服务器外的备份**：现在备份和数据在同一台服务器上，硬盘损坏会一起丢；可以定期下载到本地或上传到对象存储。
