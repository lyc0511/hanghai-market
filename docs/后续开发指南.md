## 3. 必须遵守的代码约定

### 3.1 后端

**新增一个功能的固定套路**（参考 `app/api/items.py`、`app/api/intents.py`）：

1. `app/schemas/xxx.py`：请求 / 响应模型；校验错误信息写中文（`raise ValueError("……")`）。
2. `app/api/xxx.py`：`router = APIRouter(prefix="/xxx", tags=["中文名"])`；文件开头的 docstring 写**状态流转图和本模块业务错误码**。
3. `app/main.py`：`app.include_router(xxx.router, prefix="/api")`。
4. 更新 `README.md` 的「已实现接口」「错误码」两个表。

**统一响应**：成功 `return ok(data, "提示")`；业务错误 `raise BizError(code, "中文提示")`（HTTP 200）；未登录 / 无权限由 `deps.py` 抛 401 / 403。

**登录依赖**（`app/api/deps.py`）：`get_current_user`（必须登录）、`get_optional_user`（游客也可）、`require_admin`（管理员）。

**分页**：返回 `Page(items, total, page, page_size)`（`app/schemas/common.py`）；参数 `page ≥ 1`，`page_size ≤ 50`。

**状态变更类操作**：先 `select(...).with_for_update()` 加行锁，再检查「是不是本人 / 有没有权限」和「当前状态是否允许」，最后在**同一个事务**里改状态 + 写通知 + （管理员操作）写 `audit_logs`。参考 `intents.py` 的 `lock_intent`、`admin.py` 的 `lock_pending_item`。

**通知**：用 `app/api/intents.py` 里的 `notify(db, user_id, type, title, body, link)`。已用过的 type：`intent_new / intent_accepted / intent_rejected / intent_cancelled / intent_completed / intent_closed / content_approved / content_rejected`；种子数据里还有 `club_apply / club_approved`。

**已占用的业务错误码**（新增前查一下，别撞）：

| 码 | 含义 |
|---|---|
| 40101 / 40102 / 40103 | 学号或密码错误 / 账号封禁 / 原密码错误 |
| 40301 / 40302 | 无权操作该意向 / 无权操作该物品 |
| 40401 / 40402 | 物品不存在 / 意向不存在 |
| 40901–40905 | 学号已注册 / 物品状态不能审核 / 重复意向 / 意向状态不允许 / 物品状态不允许 |
| 41301 / 41501 | 图片过大 / 格式不支持 |
| 42201–42204 | 类目错误 / 需填微信号 / 不能买自己的 / 物品不在售 |
| 42901 | 每日发布上限 |

编码规则：前三位沿用 HTTP 含义（403 无权限、404 不存在、409 状态冲突、422 参数业务错误），后两位是模块号 + 序号。建议新模块：社团用 `3x`（如 `40431` 社团不存在、`40931` 已是成员、`42231` 未在招新）、活动用 `4x`（如 `40441` 活动不存在、`40941` 已满员）、举报用 `5x`、通知用 `6x`。

**校区**：只能是 `app/core/constants.py` 里的 `CampusArea`（黄埔校区、琶洲校区）。

### 3.2 前端

- **网站页面一律用 shadcn-vue 组件**（`src/components/ui/`，需要新组件用 `npx shadcn-vue@2.9.0 add 组件名`）+ Tailwind 工具类。**不要引入 Vant 或在网站页面用 Element Plus**（Element Plus 只在 `/admin` 下用）。
- **设计规范**在 `src/styles/main.css`：颜色用 `bg-ocean / text-signal / text-buoy / bg-sail / border-fog / text-kelp`，标题用 `font-display`（得意黑）。不要写死别的颜色。
- **接口**统一写在 `src/api/index.js`，页面里不直接写 URL；请求封装 `src/api/http.js` 已处理令牌、错误提示、401 跳登录。
- **提示**：`import { toast } from 'vue-sonner'`；**确认弹窗**：`import { confirm } from '@/composables/confirm'`，`if (await confirm({ title, message, confirmText, danger })) {...}`。
- **需要登录才能做的操作**：未登录时调用 `useUserStore().openLogin()` 弹出右上角登录框，不要跳页。
- 新页面放 `src/views/`，路由加在 `src/router/index.js` 的 `SiteLayout` 子路由里（需要登录加 `meta: { auth: true }`）；内页标题用 `PageHeader` 组件；窄页面外层用 `class="container narrow"`。
- **动画要克制**（frontend-design 原则）：不要给每个区块加淡入上滑；只给「回应用户操作」的地方加（状态切换、列表重排）。
- 文案不要用「A · B · C」中点分隔、不要全大写标签。

### T08 社团目录与入社

**涉及表**：`contents`（type=`club`）、`clubs`、`club_members`、`club_applications`
**种子数据**：20 个社团（8 个招新中），145 条成员，入社申请 1 条通过 / 1 条待审（小李申请摄影协会）。

后端接口（新建 `app/api/clubs.py`）：

| 接口 | 说明 |
|---|---|
| `GET /api/clubs` | 列表：按类型（`club_type`）、是否招新、校区、关键词筛选；分页 |
| `GET /api/clubs/{id}` | 详情：简介、会长、成员数、招新信息；登录用户额外返回 `my_status`（未加入 / 申请中 / 成员 / 会长） |
| `GET /api/clubs/{id}/members` | 成员列表（分页） |
| `POST /api/clubs/{id}/applications` | 申请入社，附理由（`reason` 必填，≤300 字） |
| `GET /api/clubs/{id}/applications?status=pending` | 会长查看申请 |
| `POST /api/club-applications/{id}/approve` · `/reject` | 会长审批：通过后写 `club_members`、`member_count + 1`、通知申请人 |
| `POST /api/clubs/{id}/leave` | 成员退出（会长不能退出） |
| `GET /api/clubs/mine` | 我加入的 / 我管理的社团 |

业务规则：
- 只有 `recruit_status = 'recruiting'` 且在招新起止日期内才能申请。
- 已是成员、已有待审申请时不能重复申请（表上已有部分唯一索引 `uq_club_app_pending` 兜底，要捕获 `IntegrityError`）。
- 「会长」= `clubs.president_id`，同时 `club_members.role = 'president'`。
- `member_count` 和 `club_members` 必须在同一事务里同步更新。
- 申请提交时通知会长（type `club_apply`），审批后通知申请人（`club_approved` / `club_rejected`）。
- 🙋 需确认：会长能否编辑社团简介和招新状态（建议能）；被拒后能否再次申请（建议能）。

前端：`/clubs` 列表页（替换 `ComingSoonView`；正在招新的社团名前加**橙色信号旗**三角形，见首页现有样式）、`/clubs/:id` 详情页（申请入社按钮 + 弹窗填理由）、个人中心加「我的社团」、会长可见的「入社申请」审批页。首页「社团」板块改成真实数据（信号旗标签墙）。

验收：用小李（`20230003`）登录能看到自己对摄影协会的待审申请；用摄影协会会长（`20230004`）登录能审批；审批后成员数 +1、小李收到通知。

### T09 社团活动与报名（✅ 已完成，提交见 git 记录）

**涉及表**：`contents`（type=`activity`）、`activities`、`activity_signups`
**种子数据**：10 场活动（4 场未开始），33 条报名。

| 接口 | 说明 |
|---|---|
| `GET /api/activities` | 列表：按时间（即将开始 / 已结束）、社团、校区筛选；默认按开始时间升序 |
| `GET /api/activities/{id}` | 详情；登录用户返回 `signed_up` |
| `POST /api/activities/{id}/signup` · `DELETE …/signup` | 报名 / 取消报名 |
| `POST /api/clubs/{id}/activities` | 会长发布活动 |
| `GET /api/activities/{id}/signups` | 会长查看报名名单 |

业务规则：
- **名额并发**是本模块的重点：报名时对活动行加锁（`with_for_update`），检查 `enrolled_count < capacity` 后再 `+1`；或用 `UPDATE … SET enrolled_count = enrolled_count + 1 WHERE … AND enrolled_count < capacity` 判断影响行数。写一个并发测试：名额只剩 1 个时两人同时报名，只能成功一个。
- 报名截止时间（`signup_deadline`）之后、活动开始之后不能报名 / 取消。
- `activity_signups` 有 `(activity_id, user_id)` 唯一约束；取消报名建议改状态为 `cancelled` 并 `enrolled_count - 1`，再次报名时复用这一行。
- 🙋 需确认：活动是否只允许社团成员报名（建议全校都可以）；会长发布活动是否需要管理员审核（建议需要，复用物品审核的思路）。

前端：`/activities` 列表页（「航班表」样式：日期列 + 名称 + 主办社团 + 名额，见首页现有表格）、`/activities/:id` 详情页（报名按钮，名额进度条）、个人中心加「我报名的活动」、会长在社团详情页发布活动。首页「活动航班表」改成真实数据（即将开始的 5 场）。

验收：并发测试通过；报满后按钮变「已满员」；截止后不能报名。

## 6. 已经踩过的坑（别再踩）

| 现象 | 原因 / 解决 |
|---|---|
| 前端构建报 `No fs option provided to compileScript` | TypeScript 必须用 **5.x**（项目锁定 5.9.3）；TS 7 是 Go 重写版，没有 Vue 编译器需要的 JS API |
| 确认弹窗点「确定」无效 | 组件库会先触发「关闭」再触发按钮点击；`ConfirmHost.vue` 里关闭事件用 `setTimeout` 延后一拍判为取消。不要改回去 |
| 用脚本给输入框赋值后表单拿不到值 | shadcn 的 Input 需要真实键盘输入或正确派发事件；浏览器自动化测试请用键盘输入 |
| 浏览器控制台 `504 Outdated Optimize Dep` | Vite 首次加载新依赖时重新预构建，只在开发环境出现一次，刷新即可 |
| 页面上的时间比北京时间快 / 慢几个小时 | 浏览器按本机时区显示（开发机曾设为悉尼时区）。前端时间一律用 `src/lib/time.js` 的 `bj / formatDateTime / formatDate` 按北京时间显示，`datetime-local` 输入用 `beijingInputToIso` 加 `+08:00` 提交；**不要再直接用 `toLocaleString()`、`getHours()`** |
| Git Bash 里 psql 执行含中文的 SQL 报编码错误 | 把 SQL 写进 UTF-8 文件，用 `psql -f` 执行；Python 脚本输出中文用 `sys.stdout.reconfigure(encoding="utf-8")` |
| `theme.css` 变量和 shadcn 冲突 | 旧变量已改名为 `--hot / --line / --r`；**新代码不要再往 theme.css 加变量**，用 main.css |
| `git diff` 显示整个文件都改了 | Windows 上用 Python 文本模式写文件会把换行变成 CRLF。脚本改文件请用 `open(..., newline="
")` 或二进制模式；`components/ui/` 下 shadcn 生成的文件本来就是混合换行，**不要整体转换** |
| 运行时 `npm audit` 报 4 个高危 | 来自 `vue-router → vite → stylus → decode-uri-component`，只在构建期使用，不影响浏览器 |
